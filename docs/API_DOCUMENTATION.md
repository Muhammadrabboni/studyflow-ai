# StudyFlow AI — API Documentation

## 1. Project Overview

**StudyFlow AI** is an intelligent student task management project designed to help university students organize assignments, track deadlines, and manage their academic workload.

This API prototype provides assignment management functionality through RESTful endpoints. It uses mock in-memory data and token-based authentication.

- **Project:** StudyFlow AI
- **API Version:** 1.0.0
- **Base URL:** `http://127.0.0.1:8000`
- **Backend:** Python and FastAPI
- **Data Storage:** In-memory mock data

## 2. Authentication

The API uses HTTP Bearer token authentication.

Include the following header in requests that require authentication:

```http
Authorization: Bearer user-a-token
```

### Available mock users

| User | Token | Role | Access |
|---|---|---|---|
| User A | `user-a-token` | user | Manages their own assignments |
| User B | `user-b-token` | user | Manages their own assignments |
| Administrator | `admin-token` | admin | Manages all assignments |

Users can only retrieve, update, or delete their own assignments. Administrators can manage all assignments.

If a regular user tries to access another user's assignment by ID, the API returns `404 Not Found` to avoid revealing whether that private resource exists.

## 3. Assignment Resource

An assignment contains the following fields:

| Field | Type | Description |
|---|---|---|
| `id` | string | Unique assignment identifier, generated by the API |
| `title` | string | Assignment title, 3–100 characters |
| `description` | string | Assignment description, 1–500 characters |
| `course` | string | Course name, 2–100 characters |
| `deadline` | date | Deadline in `YYYY-MM-DD` format |
| `priority` | string | `low`, `medium`, or `high` |
| `status` | string | `pending`, `in_progress`, or `completed` |
| `ownerId` | string | ID of the user who owns the assignment |

The `id` and `ownerId` fields are generated or assigned by the server and should not be supplied when creating or updating an assignment.

## 4. API Endpoints

All assignment endpoints use the `/api/v1/assignments` resource path.

### 4.1 List assignments

**GET** `/api/v1/assignments`

Retrieves assignments accessible to the authenticated user.

Optional query parameters:

| Parameter | Type | Description |
|---|---|---|
| `course` | string | Filter by course name |
| `status` | string | Filter by assignment status |
| `deadline_before` | date | Retrieve assignments with deadlines on or before this date |
| `page` | integer | Page number; default is `1` |
| `per_page` | integer | Results per page; default is `10`, maximum is `100` |

Example:

```http
GET /api/v1/assignments?course=Machine%20Learning&page=1&per_page=10
```

Successful response: `200 OK`

```json
{
  "success": true,
  "message": "Assignments retrieved successfully.",
  "data": [],
  "meta": {
    "total": 1,
    "page": 1,
    "perPage": 10
  }
}
```

The example `data` array is shortened for documentation purposes.

### 4.2 Retrieve an assignment

**GET** `/api/v1/assignments/{assignment_id}`

Retrieves one assignment by its ID, provided the authenticated user has access to it.

Example:

```http
GET /api/v1/assignments/assignment_101
```

Successful response: `200 OK`

### 4.3 Create an assignment

**POST** `/api/v1/assignments`

Creates a new assignment for the authenticated user.

Example request body:

```json
{
  "title": "Complete Python Assignment",
  "description": "Implement functions using NumPy.",
  "course": "Machine Learning",
  "deadline": "2026-11-30",
  "priority": "high",
  "status": "pending"
}
```

Successful response: `201 Created`

The API generates the assignment ID and assigns the authenticated user as its owner.

### 4.4 Update an assignment

**PUT** `/api/v1/assignments/{assignment_id}`

Updates an existing assignment. The request must contain all required assignment fields.

Example:

```http
PUT /api/v1/assignments/assignment_101
```

Request body:

```json
{
  "title": "Updated Python Assignment",
  "description": "Complete and test the NumPy functions.",
  "course": "Machine Learning",
  "deadline": "2026-12-01",
  "priority": "medium",
  "status": "in_progress"
}
```

Successful response: `200 OK`

### 4.5 Delete an assignment

**DELETE** `/api/v1/assignments/{assignment_id}`

Deletes an assignment if it exists and the authenticated user has permission to manage it.

Example:

```http
DELETE /api/v1/assignments/assignment_101
```

Successful response: `200 OK`

## 5. Response Format

### Successful responses

Successful API responses use the following structure:

```json
{
  "success": true,
  "message": "Operation completed successfully.",
  "data": {}
}
```

For list responses, the API also includes pagination metadata:

```json
{
  "meta": {
    "total": 4,
    "page": 1,
    "perPage": 10
  }
}
```

### Error responses

Errors use a consistent structure:

```json
{
  "success": false,
  "error": {
    "code": "NOT_FOUND",
    "message": "Assignment not found."
  }
}
```

Validation errors can also include a `details` array describing invalid fields.

## 6. HTTP Status Codes

| Status | Code | Description |
|---|---|---|
| 200 | OK | Request completed successfully |
| 201 | Created | Assignment created successfully |
| 400 | VALIDATION_ERROR | Invalid or missing request data |
| 401 | UNAUTHORIZED | Missing or invalid authentication token |
| 403 | FORBIDDEN | Authenticated user is not permitted to perform the operation |
| 404 | NOT_FOUND | Requested resource does not exist or is not accessible |
| 405 | METHOD_NOT_ALLOWED | HTTP method is not supported |
| 409 | CONFLICT | Request conflicts with the current resource state |

## 7. Additional Endpoint

**GET** `/api/v1/greeting`

Returns an HTML page containing project information, team members, contributions, API status, and available endpoints.

This endpoint does not require authentication.

## 8. Interactive API Documentation

FastAPI automatically generates interactive API documentation.

- **Swagger UI:** `http://127.0.0.1:8000/docs`
- **OpenAPI JSON:** `http://127.0.0.1:8000/openapi.json`

Swagger UI can be used to explore endpoints, enter Bearer tokens, and send test requests.

## 9. Data Storage Note

This assignment uses mock in-memory data rather than a permanent database. Changes made through the API are temporary and will be lost when the server restarts.
